- 2026-10-01, lead, Remote repo created as private `Adwaitbytes/cascade` via the authenticated `gh` CLI because `GIT_REMOTE_URL` was not set. Private keeps the code unexposed until the human chooses to publish. PRD 21.4.
- 2026-10-01, lead, Generated a fresh preprod treasury mnemonic (account index 0) into `.env` because none was provided. All agent and test wallets derive from it by account index. MASTER_PROMPT 2.3.
- 2026-10-01, lead, Preprod provider is Koios (keyless) instead of Blockfrost until a Blockfrost key exists. PRD 18.1.
- 2026-10-01, lead, Toolchain pinned: Aiken v1.1.24, pnpm 12.8.1, Lucid Evolution 0.6.5, Node 20+ (machine has 26). PRD 20.1.
- 2026-10-01, lead, Config token is minted under the `cascade_node` policy; `cascade_config` spend succeeds only when the tx burns every token in the spent input. A literal "always fails" spend would make the PRD's own CloseRoot and Cancel (which burn the config token) impossible. PRD 7.1, 7.5. See docs/adr/0001-onchain-design.md section 1.
- 2026-10-01, lead, `cascade_bond` and `cascade_channel` are unparameterised and name their authority script in the datum; `cascade_node` is parameterised by their hashes and the config hash. Avoids circular script hashes. PRD 7.1.
- 2026-10-01, lead, All node logic runs in the `withdraw` handler over a `List<Action>` redeemer (stake validator pattern); spend and mint only check the zero withdrawal. Each PRD 7.5 redeemer is one `Action` constructor. PRD 7.1, 7.5.
- 2026-10-01, lead, Added `structural` and `external_lovelace` to the node datum so every value check is exact, including lovelace-denominated trees. PRD 7.4, 7.8.
- 2026-10-01, lead, `challenge_until` is fixed at Draw time (at least `min_challenge_window` after `submit_by`) instead of being set at Submit, so all deadlines are nested before money moves. PRD 7.5 Submit row.
- 2026-10-01, lead, Verifiers are siblings of the node they check (children of its parent), not its children. A child of the checked node would block its Submit through invariant 5. PRD 5.5, 11.1.
- 2026-10-01, lead, Plan leaves hash fixed-width bytes (spec hash, parent spec hash, kind, max budget, max fee) with SHA-256 and domain-separated Merkle nodes, not CBOR, so TypeScript and Aiken agree byte for byte. PRD 7.3, 9.5.
- 2026-10-01, lead, Challenged and Disputed nodes resolve in the parent's favour by a permissionless crank after `dispute_until`; bond owners reclaim unslashed bonds after `release_after`. This gives every state a deadline exit (PRD 7.5 liveness note, invariant 6).
- 2026-10-01, lead, Watchtower crank tips from structural ADA (PRD 11.5) are deferred: crankers pay their own tx fees and structural ADA returns in full to the buyer, keeping reconciliation exact. Revisit after acceptance is green.
- 2026-10-01, lead, Negative on-chain tests (A10 to A13, A19) prove failure by submitting the real transaction to preprod and recording the node's script-failure rejection, next to a passing positive control. PRD 19.2.
- 2026-10-01, lead, Unmodified Masumi agents are paid through their native `/start_job` purchase flow, with the Draw writing the same `vested_pay` lock Masumi's purchase flow writes. The x402 `masumi` method is used only on Cascade's own sell side (A6), because an x402 `masumi` lock signs x402 terms that the Masumi payment service rejects, which would leave the agent unable to submit or refund. PRD 3.3, 8.5, 9.4. Source: docs/research/x402-cardano-spec.md.
- 2026-10-01, lead, Metered leaves use Cascade's own `cascade_channel` validator instead of Subbit. Subbit needs stdlib v3.1.0, cannot be imported from its subfolder, and its close path lets the deposit go to any output, breaking the no-leak invariant. Same cumulative Ed25519 voucher model. PRD 8.6, MASTER_PROMPT Wave 2 fallback. Source: docs/research/subbit.md.
- 2026-10-01, lead, Cascade runs its own x402 facilitator (no hosted facilitator lists Cardano, and third-party facilitators reject minting transactions). PRD 8.4.
- 2026-10-01, lead, MIP-003 has 6 endpoints (4 required, `/provide_input` and `/demo` optional), not 5. Cascade agents serve all 6. `input_hash` follows MIP-004: SHA-256 of `identifier_from_purchaser + ";" + canonical JSON input`. PRD 9.1. Source: docs/research/mip-003.md.
- 2026-10-01, lead, Registry entries read from chain are trusted only after checking against the Cascade Directory allowlist, because anyone can mint under the V2 registry policy. PRD 9.3, 12.1.
- 2026-10-01, lead, Product LLM calls use OpenRouter's OpenAI-compatible API (key `OPENROUTER_API_KEY`) because no Anthropic key exists. Models are configurable by env; defaults are low-cost: planner and workers on a small fast model, Checker A and Checker B on models from two different providers (PRD 11.1 L1 "different model providers"). A spend guard reads OpenRouter's /key usage and switches to the labelled deterministic fallback before the 3 USD cap. Every call logs input and output SHA-256 (PRD 10.4). PRD 10.1, 10.4, 21.1.
- 2026-10-01, lead, Preprod indexer, directory and facilitator dedupe store use the operator's Neon Postgres. Local stack uses Postgres in Docker. PRD 17, 8.4.
- 2026-10-01, lead, `.env` values are single-quoted so the file can be sourced by shell scripts; TypeScript loads it with dotenv.
- 2026-10-01, lead, Added `AddressPayment` leaf kind (constructor 3) and a 28-byte `payee_hash` to `PlanLeaf`. A Draw may pay a key address only for a plan-bound, non-operator payee, with value capped by the leaf. This makes A5 (x402 `default` payment from the tree budget) possible without letting the orchestrator pay itself (A10). Invariant 2 restated accordingly. PRD 7.6, 8.1, 19.2 A5. ADR 0001 section 5.2.

The node checks that exactly one logic withdrawal is present and that its redeemer names the node's own hash, so logic scripts need no node-hash parameter and there is no circular dependency. PRD 7.1 lists withdraw on `cascade_node`; the withdraw-zero pattern is kept, on the logic scripts. ADR 0001 section 1.3.

- 2026-10-02, lead (cause found by W6), Masumi leaves are hired through a plan-bound Masumi purchase wallet: an AddressPayment Draw pays the exact lock value to wallet role `masumi-purchaser`, which creates the `vested_pay` lock in a plain transaction with `buyer_return_address = buyer_refund`. The Masumi Payment Service skips any lock created in a transaction with redeemers, so locks made directly by a Cascade Draw are never seen by unmodified sellers. No contract change; the signer limits the purchase wallet to approved locks and refunds. ADR 0001 section 8.1. PRD 8.5, 9.4 (payment through Masumi Payment Service or direct lock), 19.2 A3, A4.

- 2026-10-02, lead, ADR 8.1 Masumi leaves no longer nest the Masumi escrow deadlines (submit +24 h, unlock +30 h, dispute +36 h, fixed by the unmodified template) inside the parent node's window.
